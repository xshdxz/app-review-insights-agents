# 真实数据验收与证据可信度加固设计

## 背景与目标

用户使用真实 App Store URL、`评论.csv`、人工证据抽查和无密钥场景验收后，发现现有自动测试未覆盖真实交互、Apple 当前分页协议、中文导入字段、证据语义正确性和配置来源等问题。

本次修复目标是让以下场景可重复通过：

- 在线、JSON、CSV 三种数据来源具有各自清晰且可立即切换的输入界面；
- 用户提供的中文表头 CSV 能成功导入，规范英文字段仍保持兼容；
- 当前美国区 App Store 评论源能稳定获得评论，并在分页失败时保留已获取数据；
- 英文评论保留原文，同时提供可追溯的中文摘要；
- 问题发现引用的评论不仅 ID 存在，而且语义角色可复核；
- Schema、引用存在性、证据语义、追溯链和局限说明分别展示，不使用含糊的“已校验”概括所有状态；
- PRD 的目标版本与业务假设分开表达；
- 未配置、已填写待验证、已验证可调用、已显式禁用四种模型状态可区分；
- 模型失败后已有阶段输出和检查点不丢失；
- Prompt 评测在项目根目录有可直接执行的 PowerShell 入口。

## 方案选择

采用完整的证据优先方案，不采用只修界面的最小补丁，也不把关键词相似度作为语义校验结论。

关键词或字符相似度可用于诊断，但英文评论与中文问题发现之间无法可靠使用词面匹配。证据语义复核继续使用低温度、结构化 Schema 的 DeepSeek 调用，并由 Python 对输入 ID、输出 ID、角色重叠、数量阈值和持久化结果做确定性约束。

## 交互设计

### 数据来源

“数据来源”选择器移到 `st.form` 外，作为立即触发重跑的页面级控件。

- 在线采集：显示 App Store URL、评论数量和分析目标；评论数量限制为 100–500。
- JSON 导入：显示仅接受 `.json` 的上传控件、评论数量和分析目标；评论数量限制为 100–1000。
- CSV 导入：显示仅接受 `.csv` 的上传控件、评论数量和分析目标；评论数量限制为 100–1000。

三种模式使用稳定的 widget key。被隐藏模式的文件或 URL 不参与当前提交，避免旧输入误用。

### 模型状态

模型状态分为：

1. 未配置：没有有效密钥，实时开始与继续按钮禁用；
2. 已填写待验证：密钥已加载，但尚未有成功模型调用；
3. 已验证可调用：当前进程中至少一次模型调用成功；
4. 已显式禁用：`MODEL_ENABLED=false`，即使 `.env` 中存在密钥也不执行实时模型调用。

页面不显示密钥内容。状态文案说明 `.env` 仍会在 PowerShell 删除空环境变量后作为配置来源生效，避免把“清空进程环境变量”误解为“项目没有密钥”。

### 结果状态

问题发现卡片显示独立字段：

- Schema 状态；
- 引用存在性；
- 证据语义状态；
- 支持证据与冲突证据数量；
- 局限说明。

PRD 卡片单独显示“目标版本”，并将“业务假设”与“证据待确认”使用不同标签。目标版本不再只出现在折叠标题中。

## 数据导入设计

导入器继续支持现有规范字段，并新增中文别名：

| 领域字段 | 支持的主要列名 |
|---|---|
| `review_id` | `review_id`、`id`、`评论 ID` |
| `content_original` | `content_original`、`content`、`review`、`评论原文` |
| `rating` | `rating`、`评分` |
| `published_at` | `published_at`、`date`、`updated`、`发布时间` |
| `app_version` | `app_version`、`version`、`App 版本` |
| `language` | `language`、`语言` |
| `author` | `author`、`userName`、`username`、`作者` |

UTF-8 与 UTF-8 BOM 保持支持。错误仍包含行号和缺失字段，不能静默丢弃整行。

## 在线采集设计

采集器不再固定拼接已失效的分页 JSON 路径。

数据流：

1. 请求 `.../customerreviews/id={app_id}/json` 获得首批 JSON 评论；
2. 从响应的 Atom `link rel=next` 读取下一页 URL；
3. 后续页面可能返回 XML，使用标准库 `xml.etree.ElementTree` 解析 Atom 与 iTunes 命名空间；
4. 每页统一映射为 `Review`，按 `review_id` 去重；
5. 达到用户上限、没有下一页或页面没有评论时停止；
6. 首次请求完全失败时返回可操作错误；后续页失败时保留已获得评论，并通过运行局限披露实际数量。

只跟随 `https://itunes.apple.com/` 域名的下一页链接，防止上游响应把采集器引向任意地址。

## 中文摘要设计

每个批次分析结果增加 `review_summaries`：

- `review_id` 必须属于该批次；
- `summary_zh` 是忠实、简短的中文摘要，不增加原文不存在的事实；
- 中文原文可直接规范化为中文摘要，英文等其他语言由模型概括；
- Python 删除未知 ID、重复 ID和空摘要；
- 缺失摘要明确显示“待生成”，不能以空列冒充完成。

摘要随批次检查点保存。全部批次完成后，程序将有效摘要合并回清洗评论输出，因此下载 JSON、页面表格和后续恢复使用同一份数据。

## 证据语义复核设计

### 归并输入

跨批次归并不再只接收候选 Finding 和评论 ID，同时接收候选引用所对应的原始评论正文、评分、版本和语言。模型只能在该证据集合内保留、移除或改变证据角色。

### 独立复核

归并后执行证据语义复核。每个候选 Finding 的每条引用返回：

- `review_id`；
- `role`：`supporting`、`conflicting` 或 `irrelevant`；
- 简短中文判定理由。

Python 执行确定性约束：

- 删除输入集合外的 ID；
- 同一 ID 不能同时属于支持和冲突；
- `irrelevant` 不进入正式证据链；
- 语义复核后没有支持证据的 Finding 被拒绝；
- 大样本中支持证据少于阈值时标记为“假设/待确认”；
- 存在未知 ID、被移除证据或复核不完整时写入局限与 ValidationIssue；
- 只有 Schema、ID 存在性和语义复核均满足要求时，状态才显示为“证据已复核”。

复核结果和理由持久化，页面可从 Finding 展开查看引用评论的原文、中文摘要和判定理由。用户无需复制 ID 到其他工具才能核对。

### 重复发现

语义复核后增加确定性重复候选检查：当两个 Finding 的支持证据高度重叠且问题陈述指向同一场景时，标记为待合并问题；不由程序用关键词强行合并。归并 Prompt 明确禁止把“免费试用立即扣费”和“订阅取消困难”等可独立行动的问题重复或过度合并。

## Schema 与追溯状态

Provider 仍使用 Pydantic JSON Schema 校验和有限自动修复。每个成功返回的模型阶段记录 `schema_validated=true`；失败进入等待恢复状态，不保存未经 Schema 校验的阶段输出。

最终界面分别展示：

- 模型输出 Schema：通过/尚未完成；
- Finding 引用存在性：通过/有问题；
- Finding 证据语义：已复核/待确认/已拒绝；
- Review → Finding → Requirement → TestCase 追溯链：通过/有问题。

“追溯链通过”只代表链路完整，不替代证据语义复核。

## 错误处理与不中断体验

- 采集失败：保存运行与错误事件；首次失败不创建虚假评论结果。
- 模型失败：当前批次和之前阶段保持持久化，运行进入 `waiting_for_model`；恢复时沿用同一 `run_id`。
- 摘要或语义复核输出不完整：保存已通过 Schema 的原始阶段输出，确定性校验将受影响项目降级或拒绝，并记录局限。
- 无密钥或显式禁用：历史缓存、已有运行和下载仍可用，实时开始与继续按钮禁用。
- 无效密钥：允许提交，首次模型调用失败后进入等待恢复；已采集和清洗的数据仍可查看和下载。

## 人工评测入口

项目根目录新增 `run_eval.ps1`：

```powershell
.\run_eval.ps1
.\run_eval.ps1 -Live -Output output\manual-prompt-eval.json
```

脚本只负责定位项目虚拟环境并调用 `scripts/run_eval.py`，不读取或打印密钥。缺少虚拟环境或实时密钥时返回中文操作提示和非零退出码。

## 测试设计

所有行为修改遵循 RED → GREEN：先新增能复现问题的失败测试，再写最小实现。

自动化测试至少覆盖：

- AppTest 切换三种数据来源后，只出现对应输入控件；
- 开始按钮在未配置或显式禁用时不可点击；
- 用户中文表头 CSV 的 100 行可成功解析；
- Apple 首批 JSON 与后续 XML `next` 分页、去重、部分失败保留；
- 未知摘要 ID、缺失摘要、重复摘要的处理；
- 语义复核移除无关证据、交换错误角色、证据不足降级和无支持拒绝；
- 归并 Prompt 包含引用评论正文；
- PRD 目标版本与业务假设分别渲染；
- Schema、引用、语义、追溯和局限状态分别渲染；
- 无效模型密钥后运行进入等待状态，采集与清洗输出仍存在；
- 根目录评测脚本的非实时运行成功，错误路径提示可理解。

最终手工验收使用：

- `C:\Users\user\Desktop\评论.csv`；
- `https://apps.apple.com/us/app/workout-for-women-home-gym/id839285684`；
- 有效 DeepSeek 配置；
- 无效密钥；
- `MODEL_ENABLED=false`；
- JSON 样例和下载产物；
- 对每个 Finding 至少抽查一条支持证据，并重点检查低证据量、冲突证据和相似主题。
